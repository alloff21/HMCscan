# HMCscan

Веб-приложение для сводной инвентаризации IBM Power: собирает с нескольких HMC данные о серверах и разделах (LPAR) и показывает их в одном месте.

- **HMC и серверы.** Все HMC сгруппированы по ЦОД. Для каждого сервера видны процессоры и память: установлено, назначено разделам, свободно.
- **Разделы сервера.** Таблица LPAR: режим процессора (shared capped/uncapped, dedicated, donating), пул и вес, Entitled CPU, виртуальные CPU и память с границами мин / жел / макс и текущим значением, AME, режим совместимости, SRR, RMC. Клик по строке открывает карточку раздела.
- **Все LPAR.** Одна таблица по всем HMC с ЦОД, HMC и сервером, фильтрами, сортировкой, итогами и выгрузкой в CSV для Excel.
- **Администрирование — отдельный интерфейс на своём порту.** Подключения HMC (ЦОД обязателен), справочник ЦОД, пользователи, вход через Active Directory с сопоставлением групп и ролей.

Интерфейс просмотра (порт 8843) только показывает данные: в нём нет ни одной формы и ни одного запроса, который что-то меняет. Всё управление вынесено в интерфейс администрирования (порт 8844), куда могут войти только пользователи с ролью «Администратор».

HMCscan только читает данные с HMC: к `/rest/api/uom` идут исключительно GET-запросы.

## Быстрый старт

```bash
docker run -d --name hmcscan --restart unless-stopped \
  -p 8843:8843 \
  -p 8844:8844 \
  -v hmcscan-data:/data \
  -e HMCSCAN_SECRET_KEY='длинная-случайная-строка' \
  -e HMCSCAN_ADMIN_PASSWORD='пароль-admin' \
  ghcr.io/alloff21/hmcscan:latest
```

Администрирование: `https://<хост>:8844`, войдите как `admin`, добавьте ЦОД и HMC. Просмотр: `https://<хост>:8843`.

Чтобы админка была доступна только с самого сервера, публикуйте её порт на localhost: `-p 127.0.0.1:8844:8844`. Если `HMCSCAN_ADMIN_PASSWORD` не задан, пароль генерируется и печатается в лог контейнера (`docker logs hmcscan`).

Чтобы посмотреть интерфейс без HMC, добавьте `-e HMCSCAN_DEMO=1`: появятся тестовые ЦОД и HMC с вымышленными серверами.

Готовый `docker-compose.yml` лежит в корне репозитория.

### Платформы

Образ собирается под `linux/amd64`, `linux/arm64` и `linux/ppc64le`. Он работает на любом Linux с Docker или Podman, на Windows и macOS через Docker Desktop и прямо в Linux-разделе на IBM Power.

Собрать самостоятельно:

```bash
docker build -t hmcscan .
# или сразу под все платформы
docker buildx build --platform linux/amd64,linux/arm64,linux/ppc64le -t registry.local/hmcscan:1.0 --push .
```

## Подготовка HMC

Создайте на каждой HMC пользователя с ролью только для чтения и разрешите ему удалённый доступ (то же самое в GUI: Users and Security → Manage User Profiles):

```bash
mkhmcusr -u hmcscan_ro -a hmcviewer -d "HMCscan read-only"
chhmcusr -u hmcscan_ro -i "remote_webui_access=1"
```

Затем в интерфейсе администрирования (порт 8844): **ЦОД** (добавьте площадку) → **Подключения HMC** (адрес, порт 12443, пользователь, пароль, ЦОД). Кнопка «Проверить подключение» читает HMC, ничего не сохраняя.

Опрос идёт по расписанию (по умолчанию раз в 15 минут, настраивается для каждой HMC). Если HMC недоступна, показываются данные последнего успешного опроса и причина ошибки. Сервер, который видят две HMC (резервная пара), учитывается один раз.

## Active Directory

Интерфейс администрирования (порт 8844) → **Active Directory**:

1. Контроллеры домена: `ldaps://dc01.corp.local:636, ldaps://dc02.corp.local:636`.
2. Base DN, сервисная учётка (bind DN) и её пароль.
3. Группы AD и роли: например `CN=HMCscan-Admins,…` → Администратор, `CN=HMCscan-Viewers,…` → Просмотр. Вложенные группы учитываются, при нескольких группах действует старшая роль.

Доступ получают только члены сопоставленных групп. Пользователь AD появляется в списке пользователей при первом входе. Локальный `admin` работает всегда, даже если домен недоступен.

## Настройки

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `HMCSCAN_PORT` | `8843` | Порт интерфейса просмотра внутри контейнера |
| `HMCSCAN_ADMIN_PORT` | `8844` | Порт интерфейса администрирования внутри контейнера |
| `HMCSCAN_ADMIN_BIND` | `0.0.0.0` | Адрес, на котором слушает администрирование внутри контейнера |
| `HMCSCAN_TLS` | `1` | HTTPS. При `0` приложение слушает HTTP (например, за обратным прокси) |
| `HMCSCAN_SECRET_KEY` | генерируется в `/data/secret.key` | Ключ шифрования паролей HMC и AD и подписи сессий. Задайте и сохраните: при смене ключа сохранённые пароли не расшифруются |
| `HMCSCAN_ADMIN_PASSWORD` | случайный | Пароль пользователя `admin` при первом запуске |
| `HMCSCAN_SESSION_HOURS` | `12` | Время жизни сессии |
| `HMCSCAN_POLL_CONCURRENCY` | `4` | Сколько HMC опрашивается одновременно |
| `HMCSCAN_DEMO` | `0` | Демо-режим с тестовыми HMC |

### Данные и сертификат

Всё хранится в томе `/data`: база SQLite `hmcscan.db`, ключ `secret.key`, сертификат `tls/cert.pem` и `tls/key.pem`. При первом запуске создаётся самоподписанный сертификат. Чтобы использовать свой, положите `cert.pem` (с цепочкой) и `key.pem` в `/data/tls` и перезапустите контейнер.

Резервная копия — это копия тома `/data` вместе с `HMCSCAN_SECRET_KEY`.

## Как это устроено

- Python 3.12, FastAPI и Uvicorn, один процесс в одном контейнере.
- Клиент HMC REST API на httpx: `PUT /rest/api/web/Logon`, затем GET `ManagementConsole`, `ManagedSystem`, `SharedProcessorPool`, `VirtualIOServer`, `LogicalPartition`, в конце `DELETE /rest/api/web/Logon`.
- Пароли HMC и сервисной учётки AD хранятся зашифрованными (Fernet), пароли локальных пользователей — в виде scrypt-хеша.
- Интерфейс — статические HTML, CSS и JavaScript без сборки и без обращений к внешним CDN, поэтому работает в изолированной сети.

## Разработка

```bash
pip install -r requirements-dev.txt
python -m pytest
HMCSCAN_DATA_DIR=./data HMCSCAN_TLS=0 HMCSCAN_DEMO=1 python -m app   # просмотр http://localhost:8843, администрирование http://localhost:8844
```
